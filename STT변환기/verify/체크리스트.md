# STT변환기 오프라인 검증 체크리스트

인터넷이 끊긴 다른 PC(Python 미설치)에서 배포본이 그대로 동작하는지 확인하는 절차입니다. 개발 지식 없이 순서대로 따라 하면 됩니다. 각 항목의 □에 확인했으면 ☑, 확인하지 못했으면 "미확인"과 이유를 적고, 마지막 **기록표**에 옮겨 적어 개발 담당자에게 돌려줍니다.

## 0. 준비물

인터넷 PC의 `release\` 폴더에서 아래 7개 파일을 USB에 복사해 갑니다. (원내 반입 절차·백신 검사는 README.md "반입 절차"를 따릅니다.)

| 파일 | 크기(약) | 용도 |
| --- | ---: | --- |
| `STT변환기_앱.zip` | 1.4GB | 프로그램 + 기본 모델(medium) |
| `모델_small.zip` | 430MB | 작은 모델(메모리가 적은 PC용, 선택) |
| `모델_large-v3-turbo.zip` | 1.4GB | 큰 모델(선택) |
| `테스트샘플.zip` | 2MB | 검증용 .wav 7개 **(꼭 가져갑니다)** |
| `SHA256SUMS.txt` | 1KB | 해시값(파일이 손상되지 않았는지 대조) |
| `README.md` | 17KB | 설명서 사본(설치·문제 해결 참고) |
| `체크리스트.md` | 13KB | 이 체크리스트 사본 |

`README.md`와 `체크리스트.md`는 참고 문서 사본이라 `SHA256SUMS.txt`에 들어 있지 않습니다. 해시 대조(2번)는 하지 않습니다. 메모장으로 열어 읽으면 됩니다.

테스트 샘플 7개(하위 폴더 포함)와 기대 결과:

| 파일 | 기대 상태 |
| --- | --- |
| 가짜.wav | 실패(파일 손상) — 일부러 만든 가짜 파일 |
| 기본_16k.wav | 완료 |
| 무음.wav | 완료(인식된 음성 없음) |
| 빈파일.wav | 실패(파일 손상) — 0바이트 파일 |
| 스테레오_44k.wav | 완료 |
| 전화_8k.wav | 완료 |
| 하위 폴더 (2팀)\회의 #1.wav | 완료 |

→ 하위폴더 포함 시 **전체 7건 · 성공 5건 · 실패 2건**이 정상입니다. ("완료(인식된 음성 없음)"도 성공으로 셉니다.)

**여유 공간**: 이 체크리스트 전체(반입 파일 7개 보관 약 3.2GB + 앱 압축 풀기 약 1.7GB + 모델 small·large-v3-turbo 압축 풀기 약 2.1GB)에 **약 7GB**가 필요합니다. 앱만 설치하면 약 3.1GB(앱 zip 1.4GB + 푼 앱 1.7GB)가 필요하고, 해시 대조와 압축 풀기가 끝난 뒤 zip을 지우면 약 1.7GB만 남습니다. 공간이 모자라면 2번(해시 대조) 후 3번에서 푼 zip부터 지워 가며 진행합니다.

## 1. 파일 복사

- [ ] 1-1. 검증 PC에 `C:\반입` 폴더를 만들고 USB의 파일 7개를 모두 복사한다. (C 드라이브 여유 공간 약 7GB 확인: 탐색기 → 내 PC)

## 2. 해시값 대조 (파일 손상 확인)

- [ ] 2-1. 시작 메뉴에서 `cmd`를 입력해 **명령 프롬프트**를 연다.
- [ ] 2-2. 아래를 입력하고 Enter.
  ```
  cd /d C:\반입
  certutil -hashfile STT변환기_앱.zip SHA256
  ```
  (파일 이름은 앞 몇 글자만 치고 **Tab** 키를 누르면 자동으로 채워집니다.)
- [ ] 2-3. 출력된 64자리 값을 메모장으로 연 `SHA256SUMS.txt`의 같은 파일 이름 줄의 값과 비교한다. 한 글자라도 다르면 **중지**하고 다시 복사한다.
- [ ] 2-4. 같은 방법으로 `모델_small.zip`, `모델_large-v3-turbo.zip`, `테스트샘플.zip`도 대조한다.

| --- | --- |
| STT변환기_앱.zip | □ 일치 □ 불일치 |
| 모델_small.zip | □ 일치 □ 불일치 □ 안 가져옴 |
| 모델_large-v3-turbo.zip | □ 일치 □ 불일치 □ 안 가져옴 |
| 테스트샘플.zip | □ 일치 □ 불일치 |

## 3. 압축 풀기

- [ ] 3-1. `STT변환기_앱.zip`을 오른쪽 클릭 → **모두 압축 풀기** → 대상 폴더 칸을 `C:\` 로 고친다 → 압축 풀기. (1~3분 걸립니다)
- [ ] 3-2. `C:\STT변환기\STT변환기.exe` 와 `C:\STT변환기\models\medium\model.bin` 이 있는지 확인한다.
- [ ] 3-3. (가져왔다면) `모델_small.zip` → 모두 압축 풀기 → 대상 폴더를 `C:\STT변환기` 로 고친다 → `C:\STT변환기\models\small\model.bin` 이 생겼는지 확인. `모델_large-v3-turbo.zip`도 같은 방법.
- [ ] 3-4. `테스트샘플.zip` → 모두 압축 풀기 → 대상 폴더를 `C:\` 로 고친다 → `C:\테스트샘플\` 안에 .wav 6개와 `하위 폴더 (2팀)` 폴더가 있는지 확인한다.
- [ ] 3-5. 이 PC에서 예전에 STT변환기를 실행한 적이 있다면, 탐색기 주소창에 `%APPDATA%\STT변환기` 를 입력해 열고 `user_settings.ini`를 지운다. (처음 실행 상태로 만들기)

## 4. 네트워크 끊기 · Python 없음 확인

- [ ] 4-1. 랜선을 뽑고, Wi-Fi를 끈다(작업 표시줄 오른쪽 네트워크 아이콘 → Wi-Fi 끄기 또는 비행기 모드).
- [ ] 4-2. 명령 프롬프트에서 `ping 8.8.8.8` → "요청 시간이 만료되었습니다" 또는 "대상 호스트에 연결할 수 없습니다"가 나오면 끊긴 것이다.
- [ ] 4-3. 명령 프롬프트에서 `python --version` → "찾을 수 없습니다" 같은 오류가 나오거나 Microsoft Store 창이 열리면 Python이 없는 것이다(Store 창은 닫는다). 버전 번호가 나오면 기록표 비고에 적는다.

## 5. 화면 모드 첫 실행

- [ ] 5-1. `C:\STT변환기\STT변환기.exe` 를 더블클릭한다.
  - "Windows의 PC 보호" 파란 창이 뜨면 **추가 정보** → **실행**을 누른다. (서명되지 않은 프로그램이라 뜰 수 있음. 비고에 기록)
  - 백신이 막으면 중지하고 비고에 백신 이름·메시지를 적는다.
- [ ] 5-2. 처음 실행이면 "변환할 .wav 파일이 있는 폴더를 선택하세요" 창이 뜬다 → `C:\테스트샘플` 을 선택한다.
- [ ] 5-3. 프로그램 창에 대상 폴더가 `C:\테스트샘플` 로 표시되고, 오른쪽 위에 **'대상 파일 6개'**가 표시되며 목록에 **6줄**(하위폴더 제외)이 보인다.
- [ ] 5-4. **하위폴더 포함**을 체크하면 오른쪽 위가 **'대상 파일 7개'**로, 목록이 **7줄**로 바뀐다(`하위 폴더 (2팀)\회의 #1.wav` 추가).

## 6. 변환 실행

- [ ] 6-1. **시작**을 누른다. 몇 초 뒤(모델 불러오기) 변환이 시작된다.
- [ ] 6-2. 진행 중에 전체 진행률 바와 "n / 전체 7건 (xx%)", 현재 파일 이름과 파일 진행률, 목록의 상태(대기 → 변환 중 → 완료/실패)가 바뀌는 것을 확인한다.
- [ ] 6-3. 끝나면 "변환을 마쳤습니다. 전체 7건 · 성공 5건 · 실패 2건" 알림이 뜬다.
- [ ] 6-4. 목록의 상태가 위 **기대 결과** 표와 같다(가짜.wav·빈파일.wav = 실패(파일 손상), 무음.wav = 완료(인식된 음성 없음), 나머지 완료). 실패 건수는 빨간색이다.
- [ ] 6-5. 걸린 시간을 적는다: 시작 ~ 완료 알림까지 약 ______초 (참고: 개발 PC에서 medium 모델로 약 40초)

## 7. 결과 엑셀 확인

- [ ] 7-1. **결과 파일 열기**를 누르거나, `C:\테스트샘플\result\` 폴더에서 `STT_결과_YYYYMMDD_HHMMSS.xlsx`(실행 날짜·시각)를 연다. (이 PC에 엑셀이 없으면 7-2~7-4는 "미확인(엑셀 없음)")
- [ ] 7-2. 시트 이름이 `STT결과`이고 1행 머리글이 A~G열 **번호 / 파일명 / 변환 내용 / 재생 시간 / 처리 시간(초) / 상태 / 변환 일시** 이다. 머리글은 굵은 글씨·회색 배경이고 스크롤해도 고정된다.
- [ ] 7-3. 1행 머리글 아래에 결과가 **7행**(머리글 제외, 엑셀 행 번호 2~8) 있고, B열에 하위 폴더 파일이 `하위 폴더 (2팀)\회의 #1.wav` 로 표시된다. C열에 한국어 문장이 들어 있다(완료 건). D열 재생 시간이 `00:00:15` 형식이다.
- [ ] 7-4. F열 실패 2건(가짜.wav, 빈파일.wav)이 빨간 글씨로 "실패(파일 손상)" 이다. 무음.wav는 "완료(인식된 음성 없음)"이고 C열이 비어 있다.

## 11. 명령줄 모드

- [ ] 11-1. 명령 프롬프트에서 아래를 차례로 입력한다. (`start /wait`를 꼭 붙입니다. 이 프로그램은 화면용 exe라서 붙이지 않으면 끝나기를 기다리지 않습니다)
  ```
  cd /d C:\STT변환기
  start /wait "" STT변환기.exe --folder C:\테스트샘플 --no-gui --subfolders
  echo %errorlevel%
  ```
- [ ] 11-2. 변환이 끝난 뒤 마지막 `echo %errorlevel%`이 **1** 이다. (실패 2건이 있으므로 1이 정상. 0 = 모두 성공, 2 = 시작하지 못함)
- [ ] 11-3. `C:\테스트샘플\result\` 에 새 엑셀 파일이 하나 더 생겼고 결과가 7행(머리글 제외, 엑셀 행 번호 2~8)이다(결과 폴더 `result\`는 변환 대상에서 빠진다).
- [ ] 11-4. 없는 폴더로 실행하면 2가 나온다:
  ```
  start /wait "" STT변환기.exe --folder C:\없는폴더 --no-gui
  echo %errorlevel%
  ```
  (진행 문구가 명령 프롬프트 창에 보이지 않아도, 결과 파일과 종료 코드가 맞으면 통과입니다)

### 참고: Windows Sandbox로 확인하기 (개발 PC, 선택)

Windows Sandbox가 켜진 PC에서는 `verify\offline.wsb`를 더블클릭하면 네트워크가 끊기고 Python이 없는 임시 Windows에서 명령줄 모드(11번과 같은 내용)를 자동으로 실행합니다.

1. `build.bat`으로 `dist\STT변환기`를 만들고, 프로젝트 폴더에 `tests\output\sandbox` 폴더가 있는지 확인합니다(없으면 만듭니다).
2. `verify\offline.wsb` 더블클릭 → Sandbox 창이 뜨고 1~2분 뒤 스크립트가 끝납니다.
3. `tests\output\sandbox\run\` 에서 확인: `exitcode.txt`(exit_code=1), `samples\result\STT_결과_*.xlsx`(머리글 제외 7행), `logs_documents\`(이번 Sandbox 실행의 로그. 앱 폴더는 읽기 전용으로 매핑되어 로그가 Sandbox 안의 문서\STT변환기\logs에 남으므로 그것을 복사한 것), `python_check.txt`(python 없음), `network_check.txt`(응답 없음), `done.txt`.
4. Sandbox 창을 닫으면 Sandbox 안의 내용은 모두 사라집니다(결과는 3의 폴더에 남아 있음).
