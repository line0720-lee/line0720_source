# 간호도우미 운영 서버 배포 안내

## 1. 개요
- 간호부 규정·지침(PDF·DOCX)을 조항 단위로 나눠 질문에 답하는 RAG 챗봇입니다.
- 백엔드 `backend.py`(FastAPI) 하나가 화면(`index.html`)과 API를 함께 서빙합니다.
- 모델 호출(답변·임베딩)은 공유 게이트웨이를 통해서만 이루어집니다.

## 2. 필요 환경
- Windows 서버 (PowerShell)
- Python 3.10 이상 (코드 문법 기준 3.10+, 개발·테스트는 3.14)
- 게이트웨이 접속이 가능한 사내망

## 3. 설치
```powershell
cd Nurse_Guide
pip install -r requirements.txt
```
- 스캔(이미지) PDF를 읽어야 하면 선택 패키지 `pytesseract`, `pillow`와 Tesseract 프로그램(한국어 데이터 포함)을 추가로 설치합니다. 없으면 텍스트가 있는 PDF만 읽습니다.

## 4. 게이트웨이 설정
- `backend.py`의 `GATEWAY = ""` 한 곳에만 게이트웨이 주소를 입력합니다.
- 주소는 이 문서나 다른 파일·메신저에 적지 않습니다.
- 비어 있으면 `/api/chat`, `/api/embed`는 503(게이트웨이 주소가 설정되지 않았습니다)을 돌려줍니다. 자료 관리·자동 로딩은 게이트웨이 없이도 동작합니다.
- 주소는 있는데 게이트웨이에 연결할 수 없으면 `/api/embed`는 502, 질문 답변에는 "⚠️ 모델 게이트웨이에 연결할 수 없습니다."가 표시됩니다(주소는 응답에 나오지 않음).
- 입력 한도: 질문 1,000자, 참고 구간 20,000자, 임베딩 1회 64문장·문장당 8,000자 (넘으면 400).

## 5. 환경변수
| 이름 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `NURSE_ADMIN_PASSWORD` | 쓰기 기능에 필수 | (없음) | 자료 등록·수정·삭제, 분류 변경용 관리자 비밀번호. 없으면 쓰기 API가 503 |
| `NURSE_DATA_DIR` | 선택 | `Nurse_Guide\Data` | 규정·지침 파일과 `_meta.json`이 저장되는 폴더 |
| `NURSE_PORT` | 선택 | `8001` | 서버 포트 (모든 네트워크 주소 0.0.0.0 에서 대기) |

- 읽기·질문 API(화면, 자동 로딩, 자료 목록, 질문)는 인증 없이 동작합니다.
- 비밀번호가 틀리면 약 1초 늦게 401(관리자 인증이 필요합니다)로 응답합니다(무차별 대입 완화).
- 자료 등록은 본문을 받기 전에 인증·크기를 먼저 확인합니다. `Content-Length`가 없는 요청(청크 전송)은 411로 거절하므로,
  리버스 프록시를 앞에 둘 경우 요청 본문을 버퍼링해 `Content-Length`를 붙여 넘기도록 설정합니다(브라우저 업로드는 원래 붙어 있음).
- 비밀번호는 코드나 배치 파일에 적지 말고, 실행하는 창에서만 설정합니다.
- 매번 입력하기 번거로우면 `Nurse_Guide\.env` 파일(깃 제외 대상)에 `NURSE_ADMIN_PASSWORD=...` 형식으로 둘 수 있습니다.
  `python backend.py`로 직접 실행할 때만 읽으며, 이미 설정된 환경변수가 우선합니다. 형식은 `.env.example` 참고.
  서버의 `.env` 파일은 관리자만 읽을 수 있게 권한을 제한하세요.

## 6. 실행
```powershell
cd Nurse_Guide
$env:NURSE_ADMIN_PASSWORD="(관리자 비밀번호)"; python backend.py
```
- 접속: `http://서버:8001/` (포트를 바꿨다면 그 포트)
- 상태 확인: `http://서버:8001/health` → `{"status":"ok"}`

## 7. 포트·방화벽
- Windows 방화벽에서 사용하는 포트(기본 8001) TCP 인바운드를 사내망에만 허용합니다.
- 외부(인터넷)에 직접 공개하지 않습니다.

## 8. 백업
- 백업 대상: `Data\` 폴더 전체 (규정·지침 파일 + 분류·문서명·개정일·등록자 정보)
- 특히 `Data\_meta.json`은 분류와 문서 정보가 모두 들어 있으므로 반드시 함께 백업합니다.
- 저장 파일명은 무작위 이름(`xxxxxxxx.pdf`)이라 `_meta.json` 없이 복원하면 문서명·분류가 사라집니다.
- `_meta.json`이 손상되면 읽기는 "미분류"로 계속 동작하지만 저장은 막힙니다(500). 백업본으로 바꿔 넣은 뒤 다시 시도하세요.

## 9. 자료 관리 사용법 요약
1. 화면 상단의 자료 관리 버튼을 누르고 관리자 비밀번호를 입력합니다.
2. 📁 분류 관리: 분류(예: 01. 투약, 02. 감염관리)를 추가·수정·삭제하면 즉시 저장됩니다. 자료가 들어 있는 분류는 삭제할 수 없습니다(최대 99개).
3. ＋ 자료 등록: 파일(PDF·DOCX, 30MB 이하), 분류, 문서명(기본값=파일명), 개정일(YYYY-MM-DD), 등록자(필수)를 입력합니다.
   - 같은 문서명이 이미 있으면 기존 파일을 새 개정판으로 바꿀지 묻습니다.
   - 확장자와 실제 내용이 다르거나 읽을 수 없는 파일은 거부됩니다.
4. 목록의 ✏️로 분류·문서명·개정일·등록자를 수정하고, 🗑️로 삭제합니다(확인 후 삭제).
5. 창을 닫으면 자료를 다시 읽어 재색인합니다.
- `Data` 폴더에 직접 넣은 파일도 "미분류"로 읽히며, 수정하면 정보가 저장됩니다.

## 10. 게이트웨이 수령 후 확인 절차
1. `backend.py`의 `GATEWAY`에 주소를 입력하고 서버를 다시 실행합니다.
2. 임베딩 확인: `/api/embed`에 `{"texts":["테스트"]}` 한 문장을 보내 벡터가 돌아오는지 확인합니다.
   ```powershell
   Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8001/api/embed -ContentType "application/json; charset=utf-8" -Body '{"texts":["테스트"]}'
   ```
3. 화면에서 "준비 완료 — N개 파일 · N개 청크"가 나오는지 확인합니다.
4. 3단계 테스트 질문 5개를 한 번에 하나씩 실행합니다 (가상 자료 기준).
   - 투약관리지침의 투약 확인 절차 → [문서명 제N조] 출처 태그
   - 희석 기준표의 한 항목 → 출처 태그 + "※ 실제 시행 전 원문과 처방을 반드시 확인하세요."
   - 감염관리규정의 손위생 시점 → 출처 태그
   - 자료에 없는 질문 → "규정에서 확인되지 않습니다" + 미답변 목록 저장
   - 환자 개인정보 질문 → "개인정보·임상 판단은 안내하지 않습니다"

## 11. 보안 주의
- 실제 환자정보(이름, 등록번호, 진단 등)를 질문이나 자료에 넣지 않습니다.
- 관리자 비밀번호를 메신저·문서로 공유하지 않고, 담당자가 바뀌면 바꿉니다.
- 게이트웨이 주소와 서버 경로를 화면·문서·응답에 노출하지 않습니다.
