# 간호도우미 RAG 챗봇 — 단계별 프롬프트

전산도우미(`IT_Error/`)의 화면 디자인·운영 방식·기능 틀을 그대로 유지하면서,
**간호사 업무 규정·지침 원문(PDF·Word)** 을 근거로 답하는 챗봇을 만드는 순서입니다.

## 사용법
1. 아래 **[공통 규칙]** 블록을 각 단계 프롬프트 **맨 앞에 함께** 붙여넣습니다.
2. 한 번에 **한 단계만** 진행합니다. 단계 끝의 "완료 확인"을 직접 보고 나서 다음 단계로 넘어갑니다.
3. `{ }`로 표시된 값은 붙여넣기 전에 실제 값으로 바꿉니다.

| 값 | 설명 | 예시 |
|---|---|---|
| `{모델 게이트웨이 주소}` | 내 PC에서 접속되는 Ollama 게이트웨이 | `http://000.000.000.000:11500` (외부 공유 금지) |
| `{챗봇 이름}` | 화면에 표시할 이름 | 간호도우미 |
| `{소속}` | 부제 | 간호부 규정·지침 RAG 챗봇 |

> ⚠️ 시작 전 확인: 전산도우미를 점검할 때 **내 PC에서는 기존 게이트웨이(11500)에 접속되지 않았습니다**(운영 서버에서만 접속됨).
> 1단계 전에 내 PC에서 접속 가능한 게이트웨이 주소를 담당자에게 받아두세요.

| 구분 | 전산도우미 | 간호도우미 |
|---|---|---|
| 폴더 | `IT_Error/` | `Nurse_Guide/` |
| 백엔드 포트 | 8000 | **8001** |
| 화면 포트 | 3002 | **3003** |
| 자료 | Q&A Word 1개 | 규정·지침 원문 PDF·Word 여러 개 |
| 출처 표시 | `[Q번호]` | `[문서명 제N조]` / `[문서명 p.N]` |
| 문서 관리 | Q&A 편집기 | **자료 관리**(파일 등록·분류·삭제) |

## [공통 규칙] — 모든 단계 앞에 붙여넣기

```text
[공통 규칙]
- 참고 프로젝트: C:\Claude(바이브코딩)\Study\IT_Error (전산도우미). 이 폴더는 절대 수정하지 않는다. 읽기만 한다.
- 작업 폴더: C:\Claude(바이브코딩)\Study\Nurse_Guide (간호도우미)
- 포트: 백엔드 8001, 화면 3003 (전산도우미 8000/3002와 겹치지 않게)
- 실행 전 계획을 먼저 보여주고 내 승인 후 진행한다.
- 전산도우미의 화면 디자인(색상 토큰·말풍선·헤더·모달·입력창), 운영 방식(시작 시 Data 폴더 자동 로딩 → 임베딩 → 질문),
  기능(스트리밍 답변, 출처 태그, 참고 구간 펼치기, 미답변 키워드, 헤더 아이콘 새로고침, 즉시 저장 + 창 닫을 때 재색인,
  01~99 번호 표시, 등록자 필수 입력, escHtml 따옴표 이스케이프)은 그대로 유지하고, 바뀌는 부분만 바꾼다.

[보안·운영 규칙 — 반드시 지킴]
- 테스트 자료와 테스트 질문은 연습용·가상 자료만 쓴다. 실제 환자 사례·내부 통계·담당자 실명/연락처를 넣지 않는다.
- 환자명·등록번호 등 환자 개인정보, 서버 비밀번호·관리자 계정·상세 IP 대역은 입력하지 않는다.
- 화면(index.html)에서 모델을 직접 부르지 않는다. 모델 호출은 오직 백엔드(:8001)를 거친다.
- 모델 게이트웨이는 여럿이 함께 쓰는 GPU다. 한 번에 한 질문씩 테스트하고, 끝나면 백엔드를 내린다(Ctrl+C).
  게이트웨이 주소는 코드의 설정값 한 곳에만 두고 외부에 공유하지 않는다.

[기록]
- 각 단계가 끝나면 C:\Claude(바이브코딩)\Study\history\ 에 YYYY-MM-DD_간호도우미-{단계}.md 로
  목표·수행 내용·변경 파일·이슈·다음 단계를 기록한다.
```

## 1단계 — 프로젝트 복제 및 기본 정리

```text
[1단계] 전산도우미를 복제해서 간호도우미 뼈대를 만들어줘.

1. IT_Error의 backend.py, index.html을 Nurse_Guide로 복사한다.
   (Data 폴더 자료, 로그 파일, __pycache__, test_pdf.py는 복사하지 않는다. 이 프롬프트 파일은 그대로 둔다)
2. Nurse_Guide\Data 폴더를 만들고 비워둔다. 하위에 images 폴더도 만든다.
3. backend.py
   - DATA_DIR을 Nurse_Guide\Data로 바꾼다.
   - GATEWAY를 {모델 게이트웨이 주소}로 바꾼다. (MODEL, EMBED_MODEL은 그대로 qwen3.6:35b-a3b / bge-m3)
   - 실행 포트를 8001로 바꾼다.
   - SECTION_ORDER 같은 전산장애 전용 값은 지금은 그대로 두되, 다음 단계에서 정리할 목록으로 표시한다.
4. index.html
   - 제목/헤더/첫 인사를 {챗봇 이름}, 부제를 {소속}으로 바꾼다. 헤더 아이콘은 🏥 대신 🩺.
   - 운영 서버 주소 판단식은 유지하되 로컬 정적 서버 포트 기준을 3002→3003, 백엔드 주소를 http://127.0.0.1:8001 로 바꾼다
     (운영 서버 주소는 아직 없으므로 로컬 주소로 둔다).
   - 미답변 키워드 localStorage 키를 'it_unanswered' → 'nurse_unanswered'로 바꿔 전산도우미와 섞이지 않게 한다.
5. C:\Claude(바이브코딩)\Study\.claude\launch.json 에 Nurse_Guide 항목(python -m http.server 3003 --directory Nurse_Guide)을 추가한다.
6. 게이트웨이 연결을 먼저 확인한다: /api/embed 에 "테스트" 한 문장을 보내 벡터가 오는지 본다.
   실패하면 코드를 고치지 말고 원인(포트 닫힘 등)만 보고하고 멈춘다.

완료 확인:
- 백엔드(8001)와 화면(3003)이 뜨고 헤더에 "백엔드 연결됨"이 보인다.
- Data가 비어 있으므로 "읽을 수 있는 파일이 없습니다" 안내가 정상적으로 나온다.
- 전산도우미(IT_Error)는 하나도 바뀌지 않았다 (git status로 확인).
```

## 2단계 — 규정·지침 원문 파싱과 조항 단위 나누기

```text
[2단계] PDF·Word 규정·지침 원문을 조항 단위로 읽어 들이도록 백엔드를 고쳐줘.

배경: 전산도우미는 Q&A Word 1개를 Q번호 단위로 나눴고, 그 외 파일은 30줄씩 잘랐다.
간호 규정·지침은 "제1장 / 제1조(목적) / ① ② …" 구조라서 줄 수로 자르면 조항이 중간에 끊기고 출처를 정확히 표시할 수 없다.

1. 테스트용 가상 자료를 먼저 만든다 (실제 병원 규정을 베끼지 않는다):
   - Data\가상_투약관리지침.docx : 장·조·항 구조 + 표 1개(예: 가상 희석 기준표)
   - Data\가상_감염관리규정.pdf : 3쪽 이상, 장·조 구조
   - 각 문서 첫 부분에 "개정일: 2026-01-01" 같은 표기를 넣는다.
2. 백엔드 파싱 함수를 새로 만든다 (기존 _parse_qna_paragraphs는 지운다):
   - 장(제N장)·조(제N조(제목)) 경계로 나눈다. 조가 없는 지침은 제목(Heading 스타일/번호 제목) 단위로, 그것도 없으면
     기존처럼 줄 단위로 나눈다(30줄, 5줄 겹침).
   - 한 조항이 너무 길면(예: 1,500자 초과) 항(①②…) 경계에서 나누고, 나뉜 조각에도 같은 조항 정보를 붙인다.
   - Word는 doc.paragraphs만 읽으면 표가 빠진다. 본문 순서대로 문단과 표를 함께 읽고, 표는 "열1 | 열2" 형태 텍스트로 넣는다.
   - PDF는 쪽 번호를 유지한다. 글자가 거의 없는 쪽은 기존 OCR 대체 처리를 재사용한다.
   - 각 조각(청크)에 메타데이터를 붙인다: 문서명, 장, 조항(예: "제12조(투약 확인)"), 쪽(PDF), 개정일(문서에서 찾으면).
3. /api/load-data 는 파일별 원문 줄 목록이 아니라 위 청크 목록을 돌려주게 바꾼다.
   임베딩용 텍스트에는 "문서명 > 장 > 조항" 머리말을 붙여 검색이 잘 되게 한다.
4. index.html 의 autoLoadData 는 새 청크 형식을 그대로 받아 임베딩하게 바꾼다 (Q&A 전용 분기는 지운다).

완료 확인:
- 가상 자료 2개를 넣고 실행하면 "준비 완료 — 2개 파일 · N개 청크"가 나온다.
- 백엔드 /api/load-data 응답에서 조항이 끊기지 않았고, Word 표 내용과 PDF 쪽 번호가 들어 있는지 샘플 3개를 보여준다.
```

## 3단계 — 간호 업무용 답변 규칙과 출처 표시

```text
[3단계] 간호 규정·지침에 맞게 답변 규칙과 출처 표시를 바꿔줘.

1. backend.py 의 SYSTEM_PROMPT 를 간호 업무용으로 다시 쓴다:
   - 제공된 규정·지침 조각에만 근거해 한국어로 답한다. 자료에 없으면 "규정에서 확인되지 않습니다"라고 답한다.
   - 문장 끝에 출처를 반드시 단다: 조항이 있으면 [문서명 제N조], 없으면 [문서명 p.N] 또는 [문서명 제목].
   - 절차는 단계별로 줄바꿈해서 쓴다 (전산도우미 규칙 4 유지).
   - 투약 용량·희석·주입 속도·응급 처치처럼 환자 안전과 직결되는 답에는 끝에
     "※ 실제 시행 전 원문과 처방을 반드시 확인하세요." 문구를 붙인다.
   - 환자 개인정보, 특정 환자에 대한 판단 요청은 "개인정보·임상 판단은 안내하지 않습니다"라고만 답한다.
   - 같은 내용이 개정일이 다른 문서에 있으면 최신 개정일 문서를 우선하고, 다르다는 점을 알려준다.
   - think: False, /no_think 설정은 그대로 유지한다.
2. index.html
   - 답변 근거로 보내는 구간 머리말을 "[구간 N] 문서: 문서명 · 제N조 · p.N · 개정일" 형식으로 바꾼다.
   - highlightCites 정규식을 [문서명 제N조], [문서명 p.N] 형식도 출처 태그로 강조하게 고친다. [Q번호] 처리는 지운다.
   - 참고 구간 펼치기 목록에 문서명·조항·쪽·유사도를 표시한다.
   - 미답변 감지 문구를 "규정에서 확인되지 않습니다"로 바꾼다.
   - TOP_K는 4로 시작하고, 조항이 길어 답이 느리면 3으로 줄인다.
3. 아래 테스트 질문(가상 자료 기준)을 한 번에 하나씩 실행해 결과를 표로 보여준다:
   - 가상 투약관리지침의 투약 확인 절차 / 희석 기준표의 한 항목 / 감염관리규정의 손위생 시점
   - 자료에 없는 질문 1개 (미답변 목록에 저장되는지)
   - 환자 개인정보를 묻는 질문 1개 (거절되는지)

완료 확인:
- 모든 답변 끝에 올바른 [문서명 제N조] 또는 [문서명 p.N] 태그가 있고 클릭 가능한 강조로 보인다.
- 투약 관련 답변에 확인 문구가 붙는다.
```

## 4단계 — 자료 관리 화면 (문서 관리 → 자료 관리)

```text
[4단계] 전산도우미의 "문서 관리"(Q&A 편집기)를 규정·지침 파일용 "자료 관리" 화면으로 바꿔줘.
모달 모양(헤더/툴바/본문/하단 버튼), 섹션 관리 패널 방식, 01~99 번호 표시, 등록자 필수, 즉시 저장 + 창 닫을 때 재색인은 그대로 유지한다.

1. 분류(=전산도우미의 섹션) 관리
   - 예: 01. 투약, 02. 감염관리, 03. 환자안전, 04. 기록 … 최대 99개.
   - 📁 분류 관리 패널에서 추가·수정·삭제하면 즉시 저장한다. 파일이 들어 있는 분류는 삭제를 막는다.
2. 자료 등록
   - ＋ 자료 등록: 파일(PDF·DOCX만), 분류, 문서명(기본값=파일명), 개정일, 등록자(필수)를 입력한다.
   - 같은 문서명의 새 개정판을 올리면 기존 파일을 바꿀지 확인한다.
   - 파일 크기 제한(예: 30MB)과 확장자 검사를 백엔드에서 한다. 파일명은 안전한 이름으로 바꿔 저장한다(전산도우미 이미지 업로드 방식 참고).
3. 자료 목록
   - 분류별로 묶어 문서명 · 개정일 · 등록자 · 청크 수를 보여주고, 줄마다 ✏️ 수정(분류·문서명·개정일·등록자) / 🗑️ 삭제.
   - 삭제는 확인 후 진행한다.
4. 저장 방식
   - 파일은 Data 폴더에, 분류·문서명·개정일·등록자 정보는 Data\_meta.json 에 저장한다.
   - /api/load-data 는 _meta.json 의 정보를 청크 메타데이터에 합친다. _meta.json에 없는 파일은 "미분류"로 읽는다.
   - 백엔드에 /api/docs(목록), /api/docs/upload, /api/docs/{id} 수정·삭제, /api/categories 를 만든다.
5. 미답변 키워드 목록, 헤더 아이콘 새로고침은 그대로 둔다.

완료 확인:
- 가상 자료 1개를 새 분류로 등록 → 창을 닫으면 재색인되고 그 자료로 답변한다.
- 분류 이름 수정·삭제가 즉시 저장되고, 새로고침 후에도 유지된다.
- PDF·DOCX가 아닌 파일, 등록자 없는 등록은 막힌다.
```

## 5단계 — 화면 문구·디자인 마무리

```text
[5단계] 화면 디자인은 전산도우미 그대로 두고, 간호 업무에 맞게 문구와 몇 가지 편의 기능만 다듬어줘.

1. 색상 토큰·레이아웃·말풍선·다크모드는 그대로 둔다. 필요하면 --accent 색만 바꾸는 안을 2가지 보여주고 내가 고르게 한다.
2. 첫 인사 아래에 예시 질문 버튼 3개를 둔다(가상 자료 기준). 누르면 입력창에 넣고 바로 전송한다.
3. 입력창 안내 문구를 간호 업무 예시로 바꾼다. 개인정보 입력 금지 안내를 입력창 아래에 작게 한 줄 넣는다.
4. 답변 말풍선의 출처 태그를 누르면 참고 구간 목록이 펼쳐지고 해당 구간이 강조되게 한다.
5. 모바일(375px) 화면에서 헤더 버튼·자료 관리 모달이 깨지지 않는지 확인한다.

완료 확인:
- 데스크톱/모바일 스크린샷을 보여준다.
- 예시 질문 버튼, 출처 태그 클릭 동작을 직접 눌러 확인한 결과를 보여준다.
```

## 6단계 — 최종 점검과 운영 서버 준비

```text
[6단계] 운영 서버에 올리기 전에 전체를 점검하고 운영용으로 준비해줘.

1. 운영 서버용 기능 추가 (전산도우미 운영 서버에만 있고 저장소에는 없던 부분을 처음부터 넣는다):
   - 백엔드가 GET / 에서 index.html 을 직접 서빙한다 → http://서버:8001/ 로 접속하면 바로 열림.
   - 쓰기 API(자료 등록·수정·삭제, 분류 변경)는 관리자 인증을 요구한다.
     비밀번호는 코드에 쓰지 말고 환경변수(예: NURSE_ADMIN_PASSWORD)로 받는다. 읽기·질문 API는 인증 없이 둔다.
   - 화면의 백엔드 주소 판단식: 로컬 정적 서버(:3003)나 파일로 열 때만 http://127.0.0.1:8001, 그 외는 location.origin.
2. 보안 점검: escHtml(따옴표 포함) 사용 누락, 업로드 경로 조작(../), 파일 확장자 위조, 게이트웨이 주소 노출 여부.
3. 기능 점검표를 만들어 하나씩 확인한다: 자동 로딩 → 질문/출처 → 미답변 → 자료 등록/수정/삭제 → 분류 관리 → 재색인 → 인증 실패 안내.
   테스트는 Data 폴더 사본으로 하고, 끝나면 원상복구한다.
4. 운영 서버 배포 안내서를 Nurse_Guide\DEPLOY.md 로 작성한다:
   필요한 패키지(requirements.txt 버전 고정), 실행 명령, 환경변수, 포트, 백업할 폴더(Data\, Data\_meta.json).
5. 내 승인 후 git 커밋·push 한다 (Nurse_Guide 와 history 파일만, 다른 프로젝트 변경사항은 섞지 않는다).

완료 확인:
- 점검표 전 항목 결과, 발견해서 고친 문제 목록, 커밋 해시를 보여준다.
```
