## 이슈 및 해결
- 게이트웨이 주소 미수령 → 6번 보류.
- 자동 보안 검토가 복사본에서 전산도우미 원본의 문제 2건을 지적(1단계는 "그대로 복제" 범위라 지금은 고치지 않고 아래 단계에 반영):
  1. `index.html` 이미지 표시(`cited-img`, `qna-thumb`)가 파일명을 `onclick="window.open('…')"` 인라인 핸들러에 넣음.
     `encodeURIComponent`는 `'`를 바꾸지 않아 이미지 이름에 `'`가 들어가면 JS 주입 가능. `/api/qna/save`가 이미지 이름을 검사하지 않음.
     → 2단계에서 Q&A 전용 코드 삭제 시 함께 제거. 4단계 자료 관리에서 이미지·파일명을 다시 쓰면 DOM API + `addEventListener`로 만들고 서버에서 파일명 형식 검사.
  2. `backend.py` 쓰기 API(`/api/qna/save`, `/api/upload-image`)에 인증 없음 + CORS `*` + `0.0.0.0` 바인딩.
     → 6단계 관리자 인증(환경변수 비밀번호) 계획에 포함. 4단계 신규 쓰기 API(`/api/docs/*`, `/api/categories`)부터 인증 적용 구조로 만들고, CORS 허용 출처 제한도 6단계 점검표에 추가.
  - 참고: 같은 문제가 전산도우미(IT_Error) 원본에도 있음. 공통 규칙상 IT_Error는 수정하지 않으므로 사용자에게만 알림.
- `GATEWAY=""`이면 `/api/chat`·`/api/embed` 호출 시 httpx 오류(주소 없음). 서버 시작·`/health`·빈 Data 안내는 정상. 주소 입력 전까지 예상된 동작.
- `backend.py`에 "정보지원팀" 문구 2곳 남음(66행 SYSTEM_PROMPT, 318행 Q&A 저장 머리말) → 각각 3단계(프롬프트 재작성)·2단계(Q&A 코드 삭제)에서 정리.
