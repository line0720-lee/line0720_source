# 2026-10-22 간호도우미 6단계: 최종 점검과 운영 서버 준비 (+ 전체 최종 상태)

**상태: 완료. 커밋 `0d1e2b5`, origin/master에 push 완료(사용자 승인)**

## 수행 내용
- **운영용 기능**
  - `GET /`에서 `index.html`을 직접 서빙한다. 그래서 `http://서버:8001/`로 열면 바로 접속된다.
  - 화면의 주소 판단식: 로컬 정적 서버(:3003)나 파일로 열면 `http://127.0.0.1:8001`, 그 외에는 `location.origin`.
  - 쓰기 API(자료 등록·수정·삭제, 분류 변경)는 관리자 인증을 거친다.
    - `X-Admin-Password` 헤더를 환경변수 `NURSE_ADMIN_PASSWORD`와 `hmac.compare_digest`로 비교한다.
    - 환경변수가 없으면 503, 비밀번호가 틀리면 1초 지연 후 401.
    - 읽기·질문 API는 인증하지 않는다.
  - 화면은 401을 받으면 자료 관리 툴바에 비밀번호 입력칸을 보여준다. 입력값은 sessionStorage에 둔다.
  - `.env` 지원(깃 제외, `python backend.py`로 직접 실행할 때만 읽음). 형식은 `.env.example` 참고.
  - 이식성: `DATA_DIR`은 backend.py 위치 기준이고 `NURSE_DATA_DIR`, `NURSE_PORT`로 바꿀 수 있다.
  - CORS는 `localhost:3003`·`127.0.0.1:3003`만 허용한다(운영은 같은 출처).
- **보안 점검**(qa-team-final): Critical/High 0건. 아래 문제는 모두 고쳤다.
  - [Medium] Content-Length가 없는 chunked 업로드가 인증 전에 디스크에 쌓이던 문제
    → 미들웨어가 본문을 읽기 전에 411(길이 없음) → 인증 → 413 순서로 검사한다.
  - [Low-Med] 인증을 기다리는 중에 창을 닫으면 화면이 멈추던 문제 → 대기를 취소하고 finally로 상태를 되돌린다.
  - [Low] 교체 업로드 때 옛 파일 삭제 실패로 500이 나고 ID가 중복되던 문제
  - [Low] Windows 파일 잠금 때문에 메타 저장이 실패하던 문제 → 재시도한다.
  - [Low] 500 응답이 JSON 형식이 아니던 문제 → 전역 처리기를 추가했다. 게이트웨이 연결 오류는 502로 돌려준다.
  - [Low] 임시 파일이 남던 문제
  - [Low] 분류명 maxlength가 서버 제한과 다르던 문제(40 → 30)
  - [Low] 질문·임베딩 입력 길이 제한이 없던 문제
  - [Low] 비밀번호 대입 공격에 지연이 없던 문제
  - [Info] ID 검사가 줄바꿈 하나를 허용하던 문제 → fullmatch로 바꾸고 URL 변환기를 추가했다.
  - [Info] 중복 클릭 방지
  - [Info] 문서명에 대괄호를 쓰지 못하게 막았다(출처 태그와 충돌하기 때문).
- **앞 단계에서 이미 해소한 1단계 보안 지적 2건**
  - 이미지 onclick 주입 → 3단계에서 Q&A·이미지 코드를 삭제하며 해소
  - 쓰기 API 인증 없음과 CORS `*` → 6단계 인증과 CORS 제한으로 해소
- **배포 문서**: `requirements.txt`(버전 고정), `DEPLOY.md`
  - 담은 내용: 패키지, 실행 명령, 환경변수, 포트, 백업 대상(`Data\`, `Data\_meta.json`), 게이트웨이를 받은 뒤 확인하는 절차, 411·지연·502 안내
