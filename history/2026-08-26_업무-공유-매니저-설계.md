# 업무 공유 매니저 — 설계 단계 히스토리

## 작업 목표
병원 폐쇄망용 "업무 공유 매니저" 웹앱(Flask+SQLite+Bootstrap+FullCalendar) 개발.
사용자가 제공한 5W1H 정의(Part 1)와 5단계 개발 프롬프트(Part 2)를 기반으로,
superpowers:brainstorming 절차에 따라 설계를 구체화하는 중.

## 수행 내용
- Part 1(5W1H) + Part 2 1~4단계 프롬프트를 컨텍스트로 수신
- 브레인스토밍 질의응답으로 아래 사항 확정:
  - 이번 세션 범위: 1단계부터 순차 진행 (이후 2~4단계까지 확장)
  - 새 프로젝트 폴더: `task-share-manager/` (저장소 루트, 독립 프로젝트)
  - 실행 포트 5050 (기존 견적서 Flask 앱의 5000번과 충돌 방지)
  - **인증 방식**: 원래 초안엔 로그인이 없었으나(users에 비밀번호 없음), 사용자가
    "사번+이름+부서+비밀번호로 실제 로그인" 도입을 요청 → users 테이블에
    `emp_no`, `password_hash` 추가, Flask 세션 기반 인증(`@login_required`)으로 설계 변경
  - 3단계 UI의 "로그인 대체용 임시 셀렉트"는 2단계 실제 로그인과 충돌 → 실제 로그인 화면 사용으로 확정
  - 4단계 "진료현장 수기대상(수술·시술·치료)" 우선 노출은 스키마 추가 없이 카테고리로 구분하기로 확정
- 설계 문서 작성: [docs/superpowers/specs/2026-08-26-task-share-manager-design.md](../docs/superpowers/specs/2026-08-26-task-share-manager-design.md)

## 산출물
- 설계 문서: `docs/superpowers/specs/2026-08-26-task-share-manager-design.md`
- 코드/커밋: 없음 (아직 구현 미착수)

## 이슈 및 해결
- 원본 데이터 모델(Part 1)에 인증 정보가 없었는데 사용자가 로그인 기능을 요구 → 스키마에
  `emp_no`, `password_hash` 추가로 해결, 3단계 UI 설계도 그에 맞게 수정
- "수기대상(수술·시술·치료)" 개념이 기존 데이터 모델에 없어 별도 필드 신설 여부를 질문 →
  카테고리로 구분하는 방식으로 확정 (스키마 변경 없음)

## 추가 진행 (5단계 수신 및 설계 확정)
- Part 2 5단계(선택적 공유 완성 & 테스트·배포) 프롬프트 수신 → 설계 문서에 반영 완료
  - 권한 규칙 최종 점검(목록/달력 일관 적용), 담당자별 현황 요약 화면, 예외 처리 보강,
    폐쇄망 배포 가이드, 시나리오 테스트 체크리스트
- 사용자가 "실제 프로그램을 만들고 있는 게 맞냐"고 확인 → 아직 설계 문서만 있고 코드는
  없음을 명확히 안내. "5단계까지 받고 한번에 시작"으로 합의됨
- 1~5단계 설계 확정 완료, 문서 내 미해결 항목 없음

## 구현 계획 수립 완료
- superpowers:writing-plans로 13개 태스크(프로젝트 스캐폴드 → DB → 인증 API → 카테고리 API →
  업무 API → 정적자산 → 로그인화면 → 대시보드 → 카테고리관리 → 달력 → 현황요약 → README)
  구현 계획 작성: [docs/superpowers/plans/2026-08-26-task-share-manager.md](../docs/superpowers/plans/2026-08-26-task-share-manager.md)
- 백엔드(Task 2~6)는 pytest+Flask test client로 TDD, 프론트엔드(Task 8~12)는 코드 작성 후
  브라우저 수동 확인 방식
- 알려진 갭: 담당자 지정 UI가 "사용자 ID 숫자 입력"으로 단순화됨 (스펙에 사용자 목록 조회
  API가 없었음). 추후 `/api/users` 추가 여부는 별도 논의 필요
- 사용자 프로젝트 메모리 저장: `project_task_share_manager.md`
