# 업무 공유 매니저 — 설계 단계 히스토리

## 작업 목표
병원 폐쇄망용 "업무 공유 매니저" 웹앱(Flask+SQLite+Bootstrap+FullCalendar) 개발.
사용자가 제공한 5W1H 정의(Part 1)와 5단계 개발 프롬프트(Part 2)를 기반으로,
superpowers:brainstorming 절차에 따라 설계를 구체화하는 중.

## 수행 내용
- Part 1(5W1H) + Part 2 1~4단계 프롬프트를 컨텍스트로 수신
- 브레인스토밍 질의응답으로 아래 사항 확정:
  - 이번 세션 범위: 1단계부터 순차 진행 (이후 2~4단계까지 확장)
  - 새 프로젝트 폴더: `task-share-manager/` (저장소 루트, 독립 프로젝트)
  - 실행 포트 5050 (기존 견적서 Flask 앱의 5000번과 충돌 방지)
  - **인증 방식**: 원래 초안엔 로그인이 없었으나(users에 비밀번호 없음), 사용자가
    "사번+이름+부서+비밀번호로 실제 로그인" 도입을 요청 → users 테이블에
    `emp_no`, `password_hash` 추가, Flask 세션 기반 인증(`@login_required`)으로 설계 변경
  - 3단계 UI의 "로그인 대체용 임시 셀렉트"는 2단계 실제 로그인과 충돌 → 실제 로그인 화면 사용으로 확정
  - 4단계 "진료현장 수기대상(수술·시술·치료)" 우선 노출은 스키마 추가 없이 카테고리로 구분하기로 확정
- 설계 문서 작성: [docs/superpowers/specs/2026-08-26-task-share-manager-design.md](../docs/superpowers/specs/2026-08-26-task-share-manager-design.md)

## 이슈 및 해결
- 원본 데이터 모델(Part 1)에 인증 정보가 없었는데 사용자가 로그인 기능을 요구 → 스키마에
  `emp_no`, `password_hash` 추가로 해결, 3단계 UI 설계도 그에 맞게 수정
- "수기대상(수술·시술·치료)" 개념이 기존 데이터 모델에 없어 별도 필드 신설 여부를 질문 →
  카테고리로 구분하는 방식으로 확정 (스키마 변경 없음)

- 1~5단계 설계 확정 완료, 문서 내 미해결 항목 없음

## 구현 완료 (subagent-driven-development)

- `superpowers:using-git-worktrees`로 격리 워크트리(`worktree-task-share-manager` 브랜치)
  생성 후, 13개 태스크를 태스크별 구현 서브에이전트 + 리뷰 서브에이전트(스펙 준수 + 코드
  품질) 2단계 게이트로 순차 실행. 이후 전체 브랜치 최종 리뷰(opus) 1회 추가 실행.
- 구현 중 실제로 발견되어 수정된 버그들 (전부 재검토로 수정 확인됨):
  - **Task 7**: 정적 자산(Bootstrap/FullCalendar)이 `task-share-manager/static/vendor/`가
    아니라 저장소 루트 `static/vendor/`(견적서 앱 소유 폴더)에 잘못 커밋됨 → 삭제 후 정리
  - **Task 9**: `renderTasks()`에서 사용자 입력(제목/내용)을 이스케이프 없이 innerHTML로
    렌더링 → 저장형 XSS. `escapeHtml()` 헬퍼 추가로 수정
  - **Task 10**: `loadCategories()`가 select를 비우지 않고 반복 호출되어 카테고리 옵션이
    중복 누적됨 → 매 호출 시 클리어하도록 수정
  - **Task 11**: 구현 서브에이전트가 자신의 세션에서 승인된 명령을 `.claude/settings.local.json`에
    실수로 함께 커밋 — `Bash(*)`/`PowerShell(*)` 와일드카드 허용 + `defaultMode: bypassPermissions`
    추가. 컨트롤러(본 세션)가 직접 diff를 확인해 즉시 되돌리고 사용자에게 별도 보고함
  - **Task 11**: `todayStr()`가 `toISOString()`(UTC) 사용 → 한국 시간(KST) 기준 00~09시
    사이 "오늘의 주요일정"이 어제 날짜로 표시되는 버그. 로컬 날짜 계산으로 수정
  - **최종 브랜치 리뷰**: 카테고리/업무 삭제 시 FK 제약으로 500 에러(CASCADE 추가로 해결),
    앱 레벨 JSON 에러 핸들러 부재(404/405/500 핸들러 추가), FullCalendar 종료일이
    exclusive라서 다중일 업무 마지막 날짜가 달력에서 누락(보정 함수 추가), seed.py 재실행
    시 데이터 중복(멱등 처리), requirements.txt 버전 미고정(고정), `GET /api/me`가 세션
    유지 중 사용자 삭제 시 크래시 가능(404 처리 추가)
  - **컨트롤러 추가 수정**: `app.py`가 `debug=True`로 프로덕션 실행되고 있어 Werkzeug
    디버거 노출 위험 + 방금 추가한 500 핸들러가 무력화됨 → `debug=False`로 변경
- 최종 전체 테스트: 24/24 통과. 최종 리뷰 판정: "Ready to merge: Yes"
- `master`로 로컬 병합 (fast-forward, 커밋 `d9f5938`), 워크트리/피처 브랜치 정리 완료
- 병합 후 `task-share-manager/`에 venv 재생성 + DB 시드 완료 — 바로 실행 가능한 상태
