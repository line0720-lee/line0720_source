# 2026-10-22 간호도우미 4단계: 자료 관리 화면

**상태: 완료**

## 목표
전산도우미의 "문서 관리"(Q&A 편집기)를 규정·지침 파일용 "📚 자료 관리"로 바꾼다.
모달 모양, 분류(섹션) 관리 패널, 01~99 번호, 등록자 필수, 즉시 저장 + 닫을 때 재색인은 그대로 유지한다.

## 결정 사항
- **저장 위치**: 분류·자료 정보는 `Data/_meta.json`에 둔다.
  - 형식: `{"categories":[{"id","name"}], "docs":{파일명:{id,category,title,revised,author,uploaded}}}`
  - 원자적 쓰기(임시 파일 → os.replace)를 하고 asyncio.Lock 하나로 쓰기 요청을 직렬화한다.
- **분류 번호**: 01~99는 목록 순서로 매긴다. 전산도우미처럼 이름에 로마숫자를 넣지 않으므로 다시 번호 매기는 로직이 필요 없다.
- **업로드 저장 파일명**은 `uuid.확장자`다. 사용자가 보낸 파일명은 경로에 쓰지 않는다.
- **_meta에 없는 파일**(직접 넣은 가상 자료 등)은 "미분류"로 읽는다. id는 파일명 해시로 정하고, 수정할 때 메타 항목이 생긴다.
- **업로드 검사**(서버)
  - pdf/docx만 받는다.
  - 30MB를 넘으면 거절한다. 본문을 1MB씩 받으며 확인하고, Content-Length 사전 검사도 한다.
  - 내용 검사: PDF는 `%PDF-`로 시작해야 하고, DOCX는 `word/document.xml`이 든 zip이어야 한다.
  - 시험 파싱을 통과해야 한다.
- **같은 문서명**이면 서버가 409 + existing_id를 돌려준다. 화면은 "새 개정판으로 교체할까요?"로 확인한 뒤 `replace_id`로 교체한다. 기존 id는 유지하고, 옛 파일은 메타 저장이 성공한 뒤 삭제한다.
- **id 형식** `^[cd][0-9a-f]{12}$`를 검사해 경로 조작을 차단한다.
- Q&A 편집기, `/api/upload-image`, `/images`, `/api/parse-pdf`를 삭제했다. `Data/images/` 폴더는 1단계 지시대로 남겨 둔다.

## API
`GET/PUT /api/categories`, `GET /api/docs`, `POST /api/docs/upload`, `PUT/DELETE /api/docs/{id}`. 쓰기 API는 6단계 관리자 인증 대상이다.
`/api/load-data`는 `_meta`의 문서명·개정일·분류를 청크에 합치고, 응답에서 `folder`(서버 경로)를 뺐다.
